# AGENTS.md — Vicuna contributor notes

Vicuna is a minimal Ollama desktop chat client: SvelteKit + Svelte 5 + Tauri 2.
Verification is `npm test` (node-tests/), `npm run check`, `npm run build`
(and `cargo check` for the shell), plus live-browser driving the dev server.

## Layout

- `src/lib/ChatApp.svelte` — the entire app UI + interaction logic (large file, edit surgically with small `oldString` context).
- `src/lib/store.ts` — storage backends + prefs. `localStorage` on web, sqlite via `tauri-plugin-sql` in Tauri. Prefs shape: `theme | accent | fontSize | sidebarOpen | stopWords | ollamaBase` (`""` = default `http://localhost:11434`) `| zoom | defaultWorkspace | thinkLevel` (`"auto"` = model default) `| continueMode | openrouterApiKey`. sqlite keeps chats plus `meta` keys `pref_theme, pref_accent, pref_font_size, pref_sidebar, pref_stop_words, pref_ollama_base, pref_zoom, pref_default_workspace, pref_think_level, pref_continue_mode, pref_openrouter_key`.
- `src/lib/ollama.ts` — display-layer adapter (NOT inference logic): in Tauri it
  invokes the backend commands and renders streamed `Channel` events; in a
  plain browser it falls back to direct `fetch` so `npm run dev` works. `chatToTranscript`,
  `listModels/listRunning`, load/unload via `keep_alive`. `isTauriRuntime()` picks the path.
- `src/lib/markdown.ts` — marked + highlight.js + KaTeX rendering with copy-button injection.
- `src/routes/+layout.svelte` hosts the single `ChatApp` instance (`sessionId` from `page.params.id`); the `+page`/`s/[id]` pages render nothing so navigations only change the prop instead of remounting. Unknown ids redirect to `/` from inside ChatApp.
- `src/app.html` — title + pre-hydration theme flash (reads `vicuna-prefs` with `ollama-min-prefs` fallback).
- `src-tauri/src/agy.rs` — Google Antigravity (`agy acp`) as a Work engine over the same ACP client: detection, `agy models`, saved model (`agy-work.json`). One agy process per workspace (agy runs tools in its own cwd, not the session cwd); `--dangerously-skip-permissions` only when "Ask before running tools" is off; Allow/Deny cards get a Vicuna-side "Always allow" (remembered per session + tool); session/new is retried (agy's occasional "ACP session startup timed out").
- `src-tauri/src/acp.rs` — Work mode's ACP client for the user's `opencode acp` (see #55); `src-tauri/src/opencode.rs` — opencode detection, `opencode models`, saved Work model, per-process config.
- `src-tauri/` — shell + inference owner: `tauri.conf.json` (`productName: Vicuna`, `identifier: com.vicuna.app`), `Cargo.toml` package `vicuna` / lib `vicuna_lib` (+ `reqwest`, `futures-util`, `tray-icon` feature for the system tray), `src/main.rs` calls `vicuna_lib::run()`, `capabilities/default.json` includes `sql:default` + `sql:allow-execute` (the default set lacks execute — without it sqlite init fails, see console `sql.execute not allowed`). Backend commands in `src/lib.rs`: `ollama_list_models`, `ollama_list_running`, `ollama_warm_model`, `ollama_chat_stream`, `ollama_generate_stream`, `ollama_server_version`, `ollama_start_server`, `ollama_stop_server`, `zoom_apply`, `zoom_step` (Cmd/Ctrl +/−/0 drives the webview zoom — desktop shells don't do this natively; browsers are left to their native zoom), `quit_app` (explicit quit: kills self-started ollama + terminal ptys, then `app.exit(0)`). Window `CloseRequested` hides to the tray instead of quitting (streams keep running); tray menu has Show + Quit Vicuna and opens on either click, macOS dock Reopen shows.

## Storage keys (post-rebrand)

- New: `vicuna-chats`, `vicuna-model`, `vicuna-prefs`, sqlite `vicuna.db`.
- Legacy (read-only fallback, do not write): `ollama-min-chats`, `ollama-min-model`, `ollama-min-prefs`, sqlite `ollama-desktop.db`.
- `lsGet(key, legacyKey)` in `store.ts` implements the fallback. Do not remove it.

## Load-bearing decisions (do not regress)

0. **Inference lives in Rust; JS is display-only.** All Ollama traffic goes
   through `src-tauri/src/lib.rs` commands (reqwest). `src/lib/ollama.ts`
   only invokes + renders `Channel` events. Direct `fetch` to Ollama exists
   solely as the plain-browser dev fallback. Stop-button abort surfaces
   `AbortError` on the frontend; the backend request runs detached.
   Backend send failures (dead `Channel` after a refresh) break the drain
   loop instead of streaming nowhere.

8. **Refresh mid-stream resumes.** `streamInto` writes a `vicuna-pending-stream`
   marker (`chatId/index/mode/model/think/temperature/stop`) synchronously at
   start; `finally` clears it — except on page unload (`unloading` flag via
   `beforeunload`), where an abort means refresh/close and the marker must
   survive. `initApp` auto-resumes validated markers (fresh mode truncates the
   stale partial first, otherwise the from-scratch regeneration duplicates on
   append; continue mode keeps it and appends). User-Stopped streams clear the
   marker and never resume. Live-verified: reload mid-list → exact 1..100,
   no duplication, marker cleared.

1. **Continue has two routes: raw `/api/generate` (default) and native
   `/api/chat`.** Native resends the partial assistant message
   as-is (`think:false`, `temperature:0.2`, `num_ctx:32768`,
   `options.stop = stopWords`) and appends for models that continue natively
   (verified qwen3.5/gpt-oss/llama). Gemma's chat template closes the
   assistant turn, so /api/chat starts a fresh greeting; for gemma4/gemma2/3
   the default raw route instead builds the family prompt
   (`<bos><|turn>user\n…<turn|>\n<|turn>model\n<partial>`,
   stops `<turn|>`, `<|turn>`, `<|channel>`, `<channel|>`) and streams
   `/api/generate` with `raw:true` (gemma2/3 use the `<start_of_turn>` format).
   The sender is picked in `src/lib/continue.ts`; thread images or an unknown
   family always fall back to native. The raw default never sends raw prompts
   to unknown families (qwen/gpt-oss stay native): on gpt-oss-style models
   `/api/generate` with `raw:true` emits raw harmony channel tokens, ignores
   `stop`, and roleplays new turns (live-tested), which is why Auto's
   family-scoped behavior remains as the conservative option. There is
   deliberately NO sentence-boundary rewind — it caused duplication. Raw
   overruns on some builds (MLX gemma4 repeats a short phrase instead of
   emitting `<turn|>`), so `isRunawayRepetition` aborts the stream and
   `stripRunawayTail` trims the repeated run; the guard only applies to raw
   Continue. Edit saves keep assistant text exactly (trailing space matters
   when continuing), and `streamInto` drops a duplicated boundary space on
   the first token. `prefs.continueMode` (`raw|auto|native`, default raw,
   sqlite `pref_continue_mode`) is Settings → General → Continue method; it
   is also stored in the pending stream marker (`rawStyle`) so a mid-raw
   refresh resumes the same route.
2. **`/api/continue` does not exist** (verified 404 on Ollama 0.32.x). Don't try it.
3. **Custom stop words** live in prefs (`DEFAULT_STOP_WORDS` in `store.ts`), edited in Settings → General textarea (`\n` escape per line), sent only on Continue via `streamInto(..., { think:false, temperature:0.2, stop })` → `chatStream` → `options.stop`. Normal sends do not set `stop`/`temperature`.
4. **Assistant footer shows `model time tok/s` (space-separated).** `genMs` (wall-clock, accumulated across Continue and Work rounds) and `genTps` are recorded at settle, rendered in `.model-tag` (explicit `{" "}` separators — literal spaces get trimmed around block tags), and persisted to sqlite (`gen_ms`/`gen_tps`, ALTER-added). A Work turn settles stats every round, so the tag suppresses time/tok-s while that message is the live turn (`workRunning && workChatId === activeChat?.id && isLast`) — otherwise an in-progress agent looks finished. `genTps` prefers server eval stats; cloud APIs omit `eval_duration` (verified), so it falls back to eval tokens over wall time. Continue appends wall time and overwrites tok/s. `toHistory` strips stats (Ollama ignores them anyway); `onTok`/`onTh` carry them through so mid-stream renders don't drop them.
5. **Delete cascades**: deleting a user message deletes the following assistant message and vice versa, both behind confirm dialogs.
6. **Empty `done_reason:"load"`** responses mean the model was reloading; `chatStream`/`generateStream` retry up to 3x. Don't "fix" this by removing the retry.
7. **No fake macOS traffic lights, no center llama art** — removed per user request, don't re-add.
8. **Non-reasoning models reject `think:true`.** Plain models (verified: tinyllama) fail `/api/chat` with 400 `"does not support thinking"`; `chatStream` retries once with `think:false` instead of failing the turn. Don't "fix" this by defaulting think to false — reasoning models need the thinking stream.
9. **Pull/delete live in Settings → Models**, backed by `pullModel`/`deleteModel` in `ollama.ts` (`ollama_pull_model`/`ollama_delete_model` Tauri commands + direct-fetch fallback). Pull streams progress with Cancel; delete unloads first, then deletes behind a two-step confirm (`Delete` → `Confirm?`), then refreshes the list. `refreshModels` replaces the list on success (a reachable-but-empty library shows "No models installed", not the stale default).
10. **Ollama endpoint is configurable, not always localhost.** `ollama.ts` defaults to `http://localhost:11434`; Settings → General → "Ollama host" overrides it per browser (persisted in prefs; Tauri shell ignores it and always uses local Ollama). Remote use = tailscale: `tailscale serve --bg --https 11434 http://127.0.0.1:11435` + Host-rewrite proxy `/tmp/opencode/ollama-host-proxy.py` (Ollama 403s non-loopback Host headers, so plain proxying fails) + `OLLAMA_ORIGINS` including the app origin. Restarting ollama serve must re-export `OLLAMA_ORIGINS` or remote browsers get CORS failures.
11. **Ollama parallel-download sidecars are fragile.** Killing `ollama serve` mid-pull can leave 0-byte `*-partial-N` range trackers; on resume the server JSON-decodes one, gets EOF, and every pull of that model fails instantly with `{"error":"EOF"}`. Fix: delete the 0-byte sidecars (completed ranges are kept) and pull resumes. At finalize the server removes every range sidecar and aborts on the first missing one — if a resume created new gaps, recreate those sidecars as completed (`{"N":<n>,"Offset":<n*343339956>,"Size":343339956,"Completed":343339956}`) and pull again.
12. **`gemma4:e4b` default tag is broken upstream (2026-10-28).** Emits `<unusedN>`/`<tool_call|>` soup for every prompt — verified across think on/off, raw `/api/generate`, CPU-only (`OLLAMA_VULKAN=false`), and draft-disabled (`PARAMETER draft_num_predict 0`) builds. Weights hash-verify, so the published quant/packaging is at fault, not the download. Try `gemma4:e2b` or explicit `-it-q*` quants instead; `qwen3`/`llama3.1` are known-good fallbacks.
12. **Discover tab is a generated catalog, refreshed from the live registry.** `ollama.com/library` sends no CORS headers so browsers can't scrape it — instead `npm run catalog:refresh` (`scripts/refresh-catalog.py`) scrapes the library index + tags pages and sizes every variant from OCI manifests, then rewrites `src/lib/catalog.ts`. Blurbs/cats/params are hand-curated and preserved; tags + sizes refresh. Manual edits get overwritten. Weekly CI (`.github/workflows/catalog.yml`, Mondays + manual dispatch) regenerates the full catalog and opens a refresh PR — review new-model blurbs/cats before merging. The in-app **Fetch** button does the same refresh at runtime (`refreshCatalog` in `src/lib/library.ts` via the allowlisted `ollama_fetch_text` backend command — Rust has no CORS restriction) and persists the result as a `catalog` override in store (localStorage + sqlite `meta`), loaded in `initApp`. Plain browsers get a note instead (registry blocks browser CORS) — Fetch is desktop-only. `Installed`/`Discover` sub-tabs live in Settings → Models; variant `<select>` + Pull reuse `submitPullName`.
13. **Settings modal is fixed 80vw × 80vh** (capped 900×820, centered, scrolls internally) so the library fits; narrow screens keep the full-width rule.
14. **Cloud models (`:cloud` / `*-cloud`) are second-class in two places.** They never appear in `/api/ps`, so the Models tab shows a green `Cloud · ready` badge instead of Load/Unload (verified: warm succeeds but ps stays empty). Continue is disabled when a cloud model is *selected* (it generates with the selected model): the native partial-append that local models do (verified qwen3:0.6b) restarts the turn on cloud gemma (verified `gemma4:31b-cloud` returns a fresh greeting for a partial history, and raw `/api/generate` returns empty), so both Continue routes are impossible there — the button is disabled AND `continueFrom` hard-returns on `isCloudModel(selectedModel)` as defense in depth. Switching to a local model re-enables Continue on any reply.
15. **Pasted images attach as data URLs; Ollama gets raw base64.** `ChatMsg.images` (data URLs) render in the composer strip + user bubbles and persist to sqlite (`messages.images` JSON column, ALTER-added for old DBs). Transport (`toWireMessages`) strips the `data:` prefix; backend `ChatMessage.images` is `Option` + `skip_serializing_if` so text requests stay byte-identical. Text-only models 400 (`does not support multimodal`, verified pre-load on gpt-oss:20b) → `chatStream` retries stripped + `onImagesStripped` note, same shape as the think-fallback in #8. Paste reads `clipboardData.items`, downscales to 1568px JPEG via canvas (localStorage quota + context window), never dumps image bytes as text. The `+` button is image-only (`accept="image/*"`, multi-select) through the same pipeline; the old text-file attachment path is gone. All history builders go through `toHistory` so regenerate/continue/resume keep the picture.
16. **Never mutate a `$state` object through a pre-prepend raw reference.** Svelte 5 caches proxied reads at first touch (verified in `proxy.js` `get` trap: sources snapshot `target[prop]`), and even `save()`'s `JSON.stringify` cements the snapshot — later raw writes stay invisible until something writes *through* the proxy (which is why the empty-view stall "fixed itself" on first token). `send()` therefore builds a fresh session COMPLETE (user + placeholder messages) *before* `chats = [chat, ...chats]`; the old `chats = [...chats]` re-notify hack is gone. Same rule applies anywhere: finish raw construction before the object enters reactive state.
17. **Non-last regenerates ask first; the user edit box has Save + Fork & Regenerate + Regenerate.** The pencil goes straight to the edit box. User messages show (Cancel | Save | Fork & Regenerate | Regenerate): **Regenerate** on the last message regenerates directly, anywhere earlier it raises a "Regenerate here will remove N messages" confirm; **Save** rewrites just that message in history (db + UI) with no model reply, no confirm, and later messages kept; **Fork & Regenerate** forks first, then applies the edit + regeneration inside the fork. Assistant messages never regenerate, so their box keeps (Cancel | Fork & Save | Save), with Save behaving the same history-only way. The edit box supports pasting + removing images (`editImages` state, written back on save; image-only saves allowed); `saveOrConfirm`/`saveOnlyOrConfirm`/`forkAndSave` own the flow.
18. **Settings → Models shows the Ollama server itself.** A status row (`ollama_server_version`, plain `/api/version` in browser) shows `Running · vX.Y.Z` or `Not reachable`. Start/Stop exist only in Tauri: `ollama_start_server` adopts an already-running server instead of double-binding the port, and probes `ollama` at `ollama`, `/opt/homebrew/bin/ollama`, `/usr/local/bin/ollama` (Finder-launched apps get a sparse PATH). `ollama_stop_server` only kills a server Vicuna itself launched — never a foreign one. Window close hides to the tray (children keep running); only explicit Quit kills them (see #32).
19. **Copy Link is runtime-aware; desktop uses a `vicuna://` deep link.** `tauri://…` webview URLs are dead outside the app, so Tauri copies `vicuna://s/<id>` (registered via `tauri-plugin-deep-link`, schemes in `tauri.conf.json`) while browsers keep the `http…/s/<id>` link. The frontend listens (`onOpenUrl` live + `getCurrent` at launch, stashed until chats load) and navigates to the session. Scheme registration happens at install — `npm run desktop:dev` builds never claim `vicuna://`, so test links against the installed .app.
20. **One ChatApp instance for the whole app (mounted in `+layout.svelte`).** Per-route instances unmounted all state on every navigation: deleting the active chat blanked the entire sidebar until `initApp` reloaded, and `onDestroy` aborted any in-flight stream (as a fake user-stop, clearing the resume marker). Never go back to per-route instances; navigations must only change the `sessionId` prop.
21. **(Superseded by #55 — the native loop is gone.)** **Work mode uses Ollama native tool-calling, fence fallback.** `WORK_TOOLS` in `src/lib/work.ts` is passed as `tools` on `/api/chat`; `runWorkTurn` streams narration into the live message, executes native `tool_calls` via `dispatchWorkTool`, appends `formatToolResult` markdown inline (zero schema change) + `role: tool` messages to the ephemeral native history, and repeats with no round cap. Models without tools support fall back to ```tool JSON fences (parsed from display text). Unknown tool names never throw — they return an `Error: unknown tool` result so the round continues and the model refines the call; when the call carries a `command` string (the classic invented-`sed`/`grep` mistake) the error explicitly redirects to `exec` with the command filled in. A round with no real call but a call-shaped ```tool block appends a "Not executed" harness note (display-only) so hallucinations never look like ran calls. Repeat calls (same name+args already ran) trigger one wrap-up generation (ephemeral user nudge, never persisted). Tool results render as collapsed `<details class="tool-result">` (closed by default; plain-text `<summary>`, raw-HTML body since marked skips markdown inside HTML blocks). FS tools (`work_*` commands in `src-tauri/src/lib.rs`) are sandboxed to the session workspace root via `work_join` and desktop-only — plain browsers get a clean "needs desktop app" tool error, but `sessions`/`read_session` run frontend-local everywhere. `exec` runs with cwd = workspace (`cmd /C` on Windows, `sh -c` elsewhere; Windows spawns use `CREATE_NO_WINDOW` — as do the timeout `taskkill`, pid kills, and self-started `ollama serve` — so no console window flashes on the user's screen); it is governed by the system prompt's strict boundary rule (list/read/grep/write/delete only inside the workspace, no commands that reach outside; ask the user with the exact path/command before any outside access — exceptions: `read_upload` and past sessions). `ask` renders a multiple-choice card (2-8 options plus an always-present "Other" free-text field and a Dismiss button) in the live assistant message and blocks `dispatchWorkTool` until the user answers; Stop or deleting the chat resolves it with a cancel sentinel so the loop unwinds with no record, Dismiss resolves with a "do not re-ask" notice and answers resolve with the chosen text, and either outcome appends a visible `<div class="ask-log">` record (`Answer: X`, `_Dismissed_` for dismissals; the normal tool `<details>` block is skipped for `ask`, errors still show it) then returns the tool result. `say` renders normal assistant prose mid-tool-loop for models that only emit tool calls (never a tool block), and the system prompt hard-requires narration before acting (plain-text lines, or a leading `say` call). As a backstop, the tool tag itself is appended before execution (open `<details><summary>`) so `write — file.py` is visible while a slow call runs; never revert to a single post-dispatch `formatToolResult`. The old prose activity lines (`Running …` / `Using …`) were removed outright: they duplicated the tag and models imitated the "Using …" shape as plain text instead of emitting real tool calls (verified with a reasoning model echoing `Using search_code …` blocks). `toHistory`/`stripHarnessMarkup` strips tool `<details>` blocks and converts ask-logs to `Asked the user: …` prose before sending history, so models never see harness HTML to imitate (they previously fabricated blockquote and HTML answers). `Chat.mode`/`workspace` persist in sqlite (`mode`/`workspace` cols, ALTER-added) + localStorage; `prefs.defaultWorkspace` remembers the last root for "Continue in Work", whose sidebar menu row carries its own folder pill (`data-testid=continue-work-workspace`) so the folder can be changed before the click — native dialog on desktop (menu stays open), inline path form in browsers; it updates only `defaultWorkspace`/`pendingWorkspace`, never the active session's workspace. `send()` canonicalizes the workspace via `work_validate_root` before the session begins. The composer-bar workspace pill (folder icon + basename, next to `+`, work contexts only) owns workspace selection: native folder picker via `tauri-plugin-dialog` (`dialog` plugin + `dialog:default`/`dialog:allow-open` capability; browsers fall back to the in-thread input if present, else an inline popup form (Enter commits, Esc cancels, backdrop commits a typed path; an uncommitted draft commits on send)). There is no path field in the empty starter view anymore. Fresh installs set no workspace (empty — pick a folder before the first Work send). The filesystem root is refused everywhere (`work_canonical_root` rejects parentless paths; frontend treats `/` as unset): crawling `/` hits macOS TCC-protected spots (Documents, `/Volumes` network mounts) and re-prompts on every scan, so `work_tree`/`work_grep` also skip `Volumes/System/private/dev/proc/sys` while traversing. The backend strips Rust's Windows verbatim prefix (`\\?\`) in `work_validate_root`, and the pill/banner/badge render via `displayWorkspace`/`workspaceBase` (both separators) so stored verbatim paths still display cleanly. The mode toggle's selected tab is accent-filled (`.mode-toggle .seg-btn.sel`) so the active mode is unmissable. The in-thread composer workspace bar only shows while the thread has no workspace (`workspaceEditing` keeps it mounted while typing); the thread banner is the steady-state display.
22. **Streamed tokens render in ~120ms batches, never per token.** Each state write re-renders + re-highlights the whole message, so per-token writes go O(n²) on transcripts with multi-KB tool outputs and stall the UI mid-read. `streamInto` buffers into `pendingTok/pendingTh` with a 120ms `scheduleFlush`, and `finally` clears the timer + flushes synchronously so settle/resume logic always sees complete content. Separately, fenced blocks over 8KB skip highlight.js auto-detect (plain escaped text) in `markdown.ts`. Busy feedback: a 3px `.stream-bar` sits just above the composer (inside `.composer-wrap`) and shows while `streaming || workRunning`; `workRunning` spans the whole Work turn (set in `runWorkTurn`, cleared by the turn-id guard) so the bar survives tool dispatch and the wait for the next round's first token — `streaming` alone goes false between rounds. The Thinking label shimmers (`.shimmer`, gradient text) for the whole live work turn and while a chat turn is still thinking; both honor `prefers-reduced-motion`.
23. **sqlite chat saves are a serialized, coalescing single-writer, and the rewrite is ONE Rust transaction (`chats_save`).** `save()` is fire-and-forget and streaming triggers it every ~2s; overlapping full-rewrite (DELETE+INSERT) sequences interleave into UNIQUE/FK failures, and killing the app mid-storm wipes history (lost a session this way, 2026-10-29). `saveChats` now takes a snapshot, collapses late arrivals, and runs one rewrite at a time. Never fire overlapping rewrites; kill stray duplicate app instances (same DB file) on sight. **Never move the rewrite back to per-statement JS:** the plugin's `execute()` can grab a different pooled connection per call (BEGIN/COMMIT from JS is unsafe), and a page unload mid-loop — right-click → Refresh on Windows WebView2 — killed the awaiting loop right after the DELETEs landed, wiping all history (live loss, 2026-11-11; recovered by carving the WAL/free pages into `%TEMP%\vicuna-recover\recovered-final.json`). `rewriteChats` now calls the `chats_save` Tauri command, which reuses the plugin's `DbInstances` pool (`tauri_plugin_sql::{DbInstances, DbPool}`, key `"sqlite:vicuna.db"`) and runs the whole rewrite inside one `pool.begin()` transaction — a save truncated by an unload rolls back instead of truncating. The old statement loop stays only as the fallback for a stale shell without the command.
24. **Work turns are steerable: queued prompts, early tool tags, double-Esc.** While `workRunning`, the composer stays live; Send (`send()`) diverts to `queuePrompt` instead of starting a parallel turn. `takeQueued(chat.id)` is drained at the top of each agent round and appended as `role: user` in native history plus a rendered user bubble + fresh assistant bubble (mutable `curIndex` splits the turn). Leftovers at natural end start a follow-up turn; after an abort they go back into the composer (never silently dropped). Tool tags appear before execution: the loop appends `formatToolCallHead` (open `<details><summary>`) immediately, runs `dispatchWorkTool`, then appends `formatToolCallTail` — so `write — file.py` is visible while a slow call runs; never revert to a single post-dispatch `formatToolResult`. Because Ollama ships complete `tool_calls` in one chunk (verified 0.32.14 — no partial args), args generation is invisible; `streamInto` arms a 1000ms idle timer after the first token and shows a `Preparing tool call…` status (cleared on the next token or on settle). Esc once arms `escArmed` + the `Esc again to interrupt` hint for 2.5s, a second Esc calls `stop()` (`workStop` + abort); overlays that own Esc are excluded in the global handler. Message actions (edit/regen/fork/delete/continue) are gated on `busy = streaming || workRunning`, so a tool-dispatch gap can't start a parallel turn or edit the live message.
25. **Side panel has Files/Terminal tabs and is resizable.** Tab bar (`side-tabs`: tab + ×, `+` chooser, panel close) sits atop the `<aside class="explorer">`; `+` opens a popover (Explorer / Terminal). One Files view max (reopening focuses it; state is singleton and survives tab close), any number of terminal tabs (each titled with the workspace folder name). Active view renders, others `display:none`; the tree auto-refreshes when an agent turn settles and when the root changes (debounced 400ms). The panel's left edge is a drag handle (`role=slider`, keyboard ←/→/Home, double-click resets to 300px; clamped 220px–viewport-360px, in-memory width state) with hover accent line. Browsing is `work_tree` (flat depth-first, sorted, depth cap 4, 3000 entries, build dirs skipped, hidden files included) + substring search + collapsible dirs. Clicking (or double-clicking) a file opens it in the in-app editor (#63); inserting `@path` lives only in the menu's Add to chat. Right-click opens the file menu (same `.ctx-menu`; Esc closes it first): Open (in-app editor for files, OS for folders), Open in default app (`work_open_path`), Reveal in Finder, inline Rename (Enter/blur commits, Esc cancels, errors keep the box open), two-step Delete (recursive for dirs, never the root; prunes collapse state), Copy mention, Add to chat (files only); `work_rename` rejects slashes/`..`/clashes, `work_delete` refuses the root and never follows symlinks — all paths through sandboxed `work_join`. OS files *and folders* dropped on the panel import via `work_import_file` (entry-API traversal keeps relative paths, `..` stripped, 200-file/16MB caps, per-file errors aggregated); the hovered dir gets an accent tint + a "Drop to import into …" pill, root drops go to the workspace root, empty drops show a note instead of failing silently. Plain browsers get "needs the desktop app" notes. Covered headlessly: `rename_delete_roundtrip_and_guardrails` (Rust), traversal/sanitize/base64 node tests.
26. **Terminals are real ptys via portable-pty (new dep).** `term_spawn` opens the pty rooted at the canonical workspace, spawns `$SHELL -l` (fallback `/bin/zsh`; Windows starts `powershell.exe -NoLogo` directly instead of cmd — nesting PowerShell under cmd garbles PSReadLine styling; `TERM=xterm-256color`), and returns an id; a reader thread streams `TermEvent::Output` and a waiter thread reports `TermEvent::Exit` (signal deaths map to `code: None` since portable-pty reports code 1 for signals) over a Tauri Channel. `term_write`/`term_resize`/`term_kill` (kill -9 by pid, best-effort) round it out; kills are sandboxed to pids we spawned. Never leave a stray `npm run dev` running — it blocks nothing now, but kill it when done anyway.
- Work mode needs `opencode` installed (https://opencode.ai/docs/#install). `npm test` runs the Node unit tests in `node-tests/`; `cd src-tauri && cargo test` the Rust ones.

- Prefer `edit` with minimal boundary over rewriting files. Never use `shell`/comments to talk to the user. Verify by executing, don't assert from memory.
